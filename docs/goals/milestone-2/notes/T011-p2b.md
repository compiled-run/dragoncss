## R4: Blink's single-word and multi-word dispatch (read at 145.0.7632.6)

There is no separate single-word path. Two source facts settle it:

- `line_breaker.cc:1359` sends every auto-wrap text item in min-content mode to `HandleTextForFastMinContent`. Each word is added through `FastMinTextContext::Add`: `line_breaker.cc:370` takes `shape_result.CachedWidth(start, end)`, called at lines 1936 and 1944.
- `CachedWidth` (shape_result.cc 2239-2248) returns `CachedPositionForOffset(end) - CachedPositionForOffset(start)`. The positions come from two places:
  - `ComputePositionData` (shape_result.cc:2129) stores each character's position as `total_advance.ToCeil<LayoutUnit>()`, a ceiling, not a truncation;
  - `CachedPositionForOffset(length)` returns `LayoutUnit::FromFloatCeil(width_)` (shape_result.cc:2236).

So one formula covers every word: `ceil(sum to end) - ceil(sum to start)`.
- For a single word, start is 0, so it gives `ceil(width)`, which is SnappedWidth.
- For a word that starts inside the item, it can be 1 LU below SnappedWidth.

I implemented that rule as `units.ts cachedRangeWidth`, exposed through the measurer's `measureRange` and used only by min-content in `inline.ts`. It reproduces every probe (below). The deviation from the T010 text is recorded under Deviations.

## Deviations

1. **R4 is per-position ceil, not truncation.** The T010 text says "per-position truncation" because "LayoutUnit(float) truncates". At the tag, however:
   - positions are `ToCeil<LayoutUnit>` (shape_result.cc:2129);
   - the item end is `FromFloatCeil(width_)` (2236).
   The ceil form is the only one of the candidates that reproduces both the single-word probes (2845, 7911) and the multi-word probes without a special case. Pure truncation gives 2844 for the single word.
2. **`border-initial-width` uses `border-left: thick`.** The only `thick` profile row is `border-left-width:thick@block/ltr`, and a four-side `thick` would have added rows. The controls come before the registered nodes so they hold under the fault. The fixture also has `border-top: solid` as a second shorthand-omitted case.
3. **`EngineFaults` gains `initialLineWidthZoomed`, and the harness fault decoder gains its key.** The P1 corpus therefore draws from a fixed list of the 14 P1 fault names, so its inputs do not move; only the key is added.
4. **`resolve.ts` gains `isInitialByProvenance`.** An initial value has no support row before or after R5 (`support: null`); the test asserts that.
5. **Existing emitted CSS files change their line-1 compilation digest.** This is the PM ruling (option a); the bodies are byte-identical to 8228b4e.
