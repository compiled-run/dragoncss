## S3a objective (binding)
S3a (product half of S3, plus the S2 must-fix items M1-M9). (1) dragon/tree@0 finite states through the public createProject().compile()/check(): modules; several components per module, each with its own owner; component calls with finite typed arguments and state aliases, with domain checks, cycle rejection and controlled initial values; named-slot projections, where projected children keep their authored owner and inherit from the insertion parent; branch nodes with both arms checked; element nodes with static and conditional classes and attributes (Choice<V>, exactly one arm must hold); DocumentEntry.initial; scalar domains compared by type plus value (true, 'true' and 1 differ; NaN, Infinity and -0 rejected). Component-scoped style uses, ordered across several CSS files by the document's style list; a class symbol is (owner, sheet, name); selectors may test only the element itself and same-owner ancestors, plus class, compound, descendant, child and attribute presence/equality selectors for ui-* attributes. Tags stay html, body and div. (2) Per-state resolution. Enumerate every reachable assignment. If the count exceeds a named constant, block with a typed diagnostic; never truncate. Resolved results are keyed by instance-path node addresses. Web output is ready: one class per resolved variant, emitted only from the stage-1 result, with an internal assignment-to-class binding (webClassMap(compiled, assignment)). iosLayoutProjection(compiled, env, assignment). (3) Parity cases for every state (api.md §7), with no deduplication and no factoring. A new tree-fixture format: CSS files plus the tree, with spans resolved from real source text. A parity-owned authored renderer builds logical markup for each assignment from the source. It scopes classes by renaming each class token per owner in both markup and CSS, and it does not import the Dragon resolver, emitter or lowering. Both lanes run for every case. Authored captures are committed per case and stay live-equal. The report lists every case. (4) A stateCollapse fault switch: the resolver ignores the state on one element, so checked and unchecked collapse. It must fail on the named non-initial cases, and the initial cases must still pass. (5) A typed diagnostics catalogue matching api.md §6.1: Origin union, target, why, related, Fix = guarded span edits (revision and hash) or manual, plus a stale-precondition check. Also formatDiagnostic, which api.md already documents. Codes may only be added, never reused. Each catalogue entry has a message and a fix. (6) Invalid and malformed input blocks outputs, each case with a catalogue code and a span or an unlocated origin: recovered producer errors, unknown node kind, raw HTML, duplicate ids, alias cycle, alias domain mismatch, initial value outside its domain, overlapping or missing Choice arms, unknown state reference, invalid domain scalars, stale hash, and a span outside its source. (7) Negative type tests for absent target keys: outputs, targets and explain({target}); an unknown config key; Compiled<'ios'> not assignable where 'web' is required. (8) Fixtures: at least 50 in total (37 now). At least 9 new tree fixtures. They must include: the api.md §3.2 switch with two instances (16 joint cases); correlated checked&&!disabled; controlled aliases; both branch arms; named-slot projection; two components in one module with a shared class name; colliding .row across two modules; multi-file ordered sheets whose winner flips when the order is reversed.
