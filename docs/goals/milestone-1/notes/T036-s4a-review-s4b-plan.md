- **font precision rules (metric halves down, trunc(size*100)/100):** Not ChromeDeviation entries, because CSS does not define font-metric rounding. They are claims about the macOS Chrome reference that no test can fail today: the gate is at most 1 device px (compare.ts GATE_DEVICE_PX), and 1/64 exactness is informational. S4b puts them in a platform-rule registry with the MF5 shape (branches, nodes held exact at 1/64 px, platform 'darwin-arm64') and planted faults metricHalfUp and untruncatedFontSize that make named nodes non-exact. Blink font_metrics.cc at 145.0.7632.6 rounds with SkScalarRoundToScalar (halves up), so half-down on macOS comes from CoreText metric values. Lines 114-126 (Linux/ChromeOS/Android/Fuchsia only) move 1 px from ascent to descent when descent rounds down and subpixel positioning is on. For Ahem that covers 7.25, 10.3, 12, 16 and 17 px in the corpus, so Linux baselines can differ by 1 px. Both rules are macOS-keyed; S5 keys them by platform next to the UA dataset, with Linux left not captured.
- **rtl bidi fails closed:** Public path: yes. Probe /tmp/t036/p2.mts: 'AB\u200b ', ['AB\u200b',' '] and 'AB \u200b ' all give DRAGON_UNSUPPORTED_BIDI. Engine: no. Probe /tmp/t036/p4.mts: engine checkRtlText lets 'AB\u200b ' past the bidi check, while Chrome (probe /tmp/t036/p1.mts) gives it the same two-rect shape as the refused 'AB\u200b'. Must-fix M3.
- **harness :where(html){direction:rtl}:** Accepted. The emitted rtl CSS pins direction on every element (diff of tree-param-args.css against -rtl.css), so the compiled rendering does not depend on the harness, and an environment-direction fault in Dragon would fail the dual lane. No planted fault proves this yet: S4b adds ignoreEnvironmentDirection.
- **HTML rtl only via authored direction:** Enough for S4a: 58 rtl tree cases exercise the environment path in both lanes. Not enough for positioning: every position-*/flex-abspos-* HTML fixture must also run in the rtl environment (a new registry field environments: ['ltr','rtl']).
- **overflowX === overflowY validator rule:** Accepted. With Overflow limited to visible|hidden, the css-overflow-3 §3.1 pair can only compute to equal axes. Revisit if clip or auto is admitted.
- **C6 exception:** Accepted. Probe /tmp/t036/p3.mts: '.a { ; width: 50px; ; }' and '<!-- .a{...} -->' apply in Chrome and Dragon alike. A top-level ';' (which Chrome treats as starting a dropped rule prelude) gives DRAGON_CSS_PARSE, so it is not silently accepted.
