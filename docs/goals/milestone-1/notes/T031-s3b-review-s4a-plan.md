## S4a objective (binding)
S4a (task id suggested T035; note docs/goals/milestone-1/notes/T035-slice-4a.md). PART A: engine flow features, each proven against Chrome at the unchanged 1 device px gate. (A1) direction: rtl. Covers: block width with over-constrained margins (CSS2 §10.3.3, where rtl ignores margin-left) and auto margins, including odd-LU free space; text-align start/end/left/right/center on wrapped text, including odd-LU center and overflowing lines, which are start-aligned and so overflow to the left; flex main axis in rtl; justify-content start/end/left/right/flex-start/flex-end; cross-axis start/end/self-start/self-end in column containers. Bidi: text in an rtl context may hold only strong-L Ahem letters, space and U+200B, unless the Worker implements UAX #9 W/N/L1 for the accepted ASCII set and proves it with a fixture that puts punctuation and digits at run and line ends. Otherwise the engine raises a new typed UnsupportedCode ('bidi-neutral'). It never lays out neutrals as if they were ltr. (A2) order (css-flexbox-1 §5.4), with negative and equal values and the stable order-modified document order, including anonymous flex items. (A3) row-reverse and column-reverse, crossed with justify-content (start is not flex-start), auto margins and rtl. (A4) wrap-reverse, crossed with align-content and align-items flex-start/start/end and with baseline. (A5) Baseline: align-items and align-self baseline and first baseline. The first baseline comes from the first line box (line top plus floored half-leading plus ascent) and goes down through block children and anonymous blocks. A flex container's own baseline follows css-flexbox-1 §8.5, and nested flex baseline is covered. When there is no baseline, a synthesized fallback is measured in Chrome. Baseline in column containers takes the fallback alignment. last baseline and align-content: baseline stay unsupported (DRAGON_UNSUPPORTED_VALUE and flex-baseline respectively). (A6) overflow: hidden on both axes makes a scroll container. Its automatic minimum size is 0 (§4.5). It is a BFC root, so parent/child margins stop collapsing and collapse-through stops. It is also measured as a flex item and as a baseline source. The resolver implements the css-overflow-3 §3.1 computed pair rule (visible or clip next to hidden computes to auto). Any computed auto, scroll or clip is DRAGON_UNSUPPORTED_VALUE. iOS clipping is a paint aspect and is never exact. PART B: coverage. (B1) The internal Environment gains direction ('ltr' | 'rtl'), as api.md §7 requires. The environment direction reaches the root as a compiler-resolved value with origin 'environment', never as an author declaration. Both renderings receive it through one harness mechanism, and the dual lane must stay exactly equal for every longhand. If a dir attribute changes any other computed longhand (for example unicode-bidi), use the data-dragon-harness style. (B2) Every case of every tree fixture also runs in the rtl environment. The case id takes a suffix. Nothing is deduplicated, including cases whose layout is symmetric. The MF1 hand declarations in fixture.json cover both environments, and the declared, renderer and Dragon counts and the initial cases are checked per environment. (B3) Profile contexts gain a direction facet, computed from the resolved direction. The flex text contexts (text-in-flex-item, text-as-anonymous-flex-item) gain a main-axis facet (row or column). Each resulting text row context needs a passing case with 2 or more lines. An unproven context blocks with DRAGON_UNPROVEN_CONTEXT, and rows are never keyed by geometry. (B4) At least 75 layout fixtures (reject fixtures excluded) and at least 17 new ones. They cover A1-A6 and include the cross-products named above. Add at least one reject fixture each for a bidi-neutral refusal (or its proof), last baseline, and overflow: auto or scroll. (B5) Planted engine faults through layoutWithFaults. Each must fail its named fixture on the layout lane while chrome-dual passes, and pass with the fault off: rtlAsLtr (text-align start in rtl treated as left), ignoreOrder, baselineFromBorderTop and scrollMinAuto (a scroll container keeps its auto minimum). Remove every UnsupportedCode that becomes dead; the every-code-raised test stays. PART C: S3b must-fix items. (C1) Fractional text. Add a fixture with fractional px font sizes (for example 10.3px, 12.5px and 13.7px) and fractional line heights (px, and numbers giving non-whole LU). It has wrapped lines where two or more leaves share a line, and center and end alignment. It must pass at the gate. If it cannot, narrow the font-size and line-height value subsets to whole px so that fractional values are DRAGON_UNSUPPORTED_VALUE, and report the numbers. The gate is never loosened. (C2) A line-mapping edge fixture. A tree fixture works if needed. It covers: a surviving whitespace-only :space<k> node in the middle of a line (recorded with rects); one at a line break (no rects on either side); a leaf that is only U+200B; a leaf boundary exactly at a break; a leaf that starts a line. Every Chrome rect maps one-to-one, and no rect is filtered. (C3) The validator gets a new code, 'anonymous-shape': an anonymous box has at least one child, all its children are text leaves, and its display is block. A compiler test checks that every anonymous box in every lowered case takes its inherited longhands from its parent and every other longhand at its webref initial value. (C4) One display:none rule in the lowering. Either display:none subtrees are omitted everywhere (CSS2 §9.2.4) or they are kept everywhere. A test shows that a hidden subtree beside text and one elsewhere give the same diagnostics and projection outcome. (C5) The lowering asserts that each text leaf's resolved text-align equals its containing block's (element or anonymous) lowered textAlign, with a test. This holds in both directions. (C6, PM addition from T034) Nested rules and nested at-rules inside a rule block are silently skipped today (packages/dragon/src/css/stylesheet.ts parseStylesheet: `if (d.type !== 'Declaration') continue;`). Every non-declaration child of a rule block must produce a typed DRAGON_* diagnostic (catalogue entry with fix) and block affected outputs, with a reject fixture (CSS nesting with &).
