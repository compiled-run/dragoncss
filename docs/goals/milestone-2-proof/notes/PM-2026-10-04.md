## MQ-R0 ruling: fix a shipped web @media bug at fractional widths

**The bug:** Chrome allows 1/64 px of slack on `<=`, `>=` and `=`, while `<` and `>` are exact. When the two share a threshold (as media-range's `width < 400px`, `400px <= width` and `width = 400px` do), three bands exist only at fractional widths (399.984375–400.015625). Master's web output has no block for them, so at fractional widths (browser zoom, iframes) classes lose their styles in Chrome.

**PM ruling:** media-range's emitted CSS and its expected-media records may change (6 bands become 9), as an intended correction. The media sweep must sample fractional-only bands through an exact-device-px iframe, and "every band is sampled" stays fully strict, with a planted fault. Any other existing output change is still a stop.

**Correction to the T067 spec's Finding 1:** integer thresholds can still be wrong at fractional widths when strict and slack comparisons share a value.

## Owner ruling: "not applicable on native" is a third verdict (NA-NATIVE)

**Owner, 2026-10-04:** Dragon supports CSS on native; it is not a browser. Declarations with no meaning on a touch-native platform must not count as unsupported.

**The verdict:** besides supported and refused, a declaration can be **not applicable on native** (iOS and Android).
- The compiler accepts it, emits nothing for it on native, and reports an info-level diagnostic (not an error).
- Web output is unchanged and must stay Chrome-exact.
- Support numbers (profiles, north star) count these separately and leave them out of the denominator. They are never counted as supported.

**Guard rails (binding):**
- Every entry is on an explicit, reviewed list with a one-line reason. Nothing is not-applicable by default; anything off the list is still refused ("missing data means unsupported").
- An entry qualifies only if it has no visible or behavioural effect a native user could observe. Anything with a visible native effect needs real support. Examples: `scrollbar-width: none` hides scroll indicators; `-webkit-appearance: none` changes form-control rendering.
- Each entry has a test proving it compiles clean and changes nothing on native, and that web is unchanged.
- The owner may veto any entry in the PR.

**Proposed first list (the lane confirms each against the code):**
- `cursor`
- `will-change`
- `scrollbar-color`
- `::-webkit-scrollbar`, `::-webkit-scrollbar-thumb` and `::-webkit-scrollbar-track` rules
- `::-moz-range-thumb` and `::-webkit-slider-thumb` rules (pending the FORM-a decision on range inputs)
- `color-scheme` (only if Dragon doesn't follow system dark mode; otherwise it needs real support)

**Not on the list:** `scrollbar-width` and `-webkit-appearance`. Both are real support work.

**Lane:** NA-NATIVE, one small PR from master.
