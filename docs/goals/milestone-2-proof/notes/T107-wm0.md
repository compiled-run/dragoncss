## What changed

- **properties/writing-mode.ts (new).** Adds three shorthands with no longhands: writing-mode, text-orientation and text-combine-upright. It also defines:
  - HORIZONTAL_WRITING_MODES = horizontal-tb, lr, lr-tb, rl, rl-tb.
  - WRITING_MODE_RESET_LONGHANDS = { writing-mode: horizontal-tb }, used for computedExtra.
  - properties.ts appends the family's aggregates.
- **shorthands/writing-mode.ts (new) and the index.ts registry.**
  - writing-mode refuses every non-horizontal keyword with `DRAGON_UNSUPPORTED_VALUE` on the value span. That covers vertical-rl, vertical-lr, sideways-rl, sideways-lr, tb and tb-rl.
  - text-orientation accepts all of mixed, upright and sideways, as inert.
  - text-combine-upright accepts none and all. It refuses `digits`, because Chrome 145 does not parse it (probe: the specified value is empty).
  - CSS-wide keywords set nothing.
- **scripts/gen-css-grammar.ts.** Adds the family to SUBSET. Its SYNTAX_EXTENSIONS entry adds the SVG 1.1 writing-mode values (lr, lr-tb, rl, rl-tb, tb, tb-rl; css-writing-modes-4 Appendix B), which webref omits. grammar.generated.ts is regenerated from it.
- **computedExtra, additive only.**
  - internal.ts exports WRITING_MODE_RESET_LONGHANDS and WritingModeResetLonghand.
  - In parity, the fixtures.ts type is widened, and dual.ts looks up both reset tables.
- **fixture-groups/writing-mode.ts, registered in fixtures.ts.** Two layout fixtures, each run in ltr and rtl, with computedExtra writing-mode:
  - writing-mode-horizontal: every accepted keyword, uppercase, inherit, initial and unset, flex, rtl.
  - writing-mode-inert-text: text-orientation and text-combine-upright on Ahem text.
  - Five reject fixtures: vertical-lr, sideways-rl, tb, tb-rl, and text-combine digits.
- **Pinned retargets (Throughput Rules):**
  - logical-props.ts `reject-writing-mode`: DRAGON_UNSUPPORTED_PROPERTY becomes DRAGON_UNSUPPORTED_VALUE, still on vertical-rl. The span is now the value `vertical-rl`, because a value refusal points at the value.
  - logical.test.ts "out of scope stays refused": vertical-rl and vertical-lr now expect DRAGON_UNSUPPORTED_VALUE. horizontal-tb was dropped from that list because it is now accepted. The logical radius corners are unchanged.
  - seams.test.ts: the SHORTHANDS order pin appends the three properties.
- **test/writing-mode.test.ts (new), 24 tests.** Covers the registry, parse and refusals, compile inertness (web and iOS outputs are byte-identical apart from the compilation header), and blocking.
  - It also runs the live Chrome 145 dual computed check: Dragon accepts a keyword exactly when Chrome computes it to horizontal-tb. It asserts that lr, lr-tb, rl and rl-tb compute to horizontal-tb, and that tb and tb-rl compute to vertical-rl, which agrees with WM-P T106.
  - Plant verticalAcceptedAsHorizontal:
    - As a test-side handler, the Chrome check catches it on all six vertical keywords.
    - Through compareDual on the committed capture, the dual lane reports `a1: writing-mode authored "vertical-rl" compiled "horizontal-tb"`.
    - As a source mutation (accept everything), 9 tests fail. The source was restored afterwards.
