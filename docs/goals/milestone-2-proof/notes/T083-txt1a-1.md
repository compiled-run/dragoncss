## T083J amendment (Judge, 2026-09-30), PM accepted

The Worker stopped before any edit: the spec assumes every FIXTURES layout case has a native lowering. The Worker proposed a FixtureSpec flag, and the Judge rejected it. A flag in FIXTURES reaches targets.ts (S16) through layoutCaseIds() for every device lane, plus native-build, break-capture and nativeCases, which is a device-coverage shrink risk.

The ruling follows T038 ruling 10.

**Registry.** Text-latin cases form their own registry, TEXT_LATIN_FIXTURES, in fixture-groups/text-latin.ts. They are kept out of FIXTURES, so device coverage cannot change by construction; the rejects go in FIXTURES.

**Guard test.** text-latin.test.ts admits a case, in both directions, only when all of these hold:
- web output is ready;
- engineLayoutProjection is ready and nativeLayoutProjection is blocked;
- ios and android are blocked only by DRAGON_UNSUPPORTED_FONT diagnostics from the checkFonts deferral Set;
- at least one non-Ahem text face is laid out;
- no id is shared with FIXTURES.

Two negative tests: an Ahem FIXTURES case placed in the registry throws, and a Lato case with one non-font error also throws.

**Phase A** (its own checkpoint commit):
- shapedMeasurerFor in platform.ts. measurerFor and its Ahem-only callers (wpt, gen-baseline-source-matrix, the line-breaks.ts hosts, native-host referenceMeasurer, lanes reference rows) stay unchanged, because they mirror the device runtime.
- TextFont.face and FontSpec.face, with the Ahem inputs migrated by generator.
- pipeline, dpr, vectors and platform-check use the Node HarfBuzz shaper for Ahem.
- R5 (a) and the EngineFaults plants.
- Every existing output must stay byte-identical.

**Phase B:**
- lowerTree gets a mode, 'native' | 'engine'. Native mode keeps today's Ahem-only refusal exactly. Engine mode accepts bundled, static, Latin, non-synthetic faces.
- project.ts: when every native blocker is a checkFonts font deferral for a node engine mode accepts, lower in engine mode and store engineLowered, which is the same object as nativeLowered when native is checked.
- internal.ts appends engineLayoutProjection.
- runCase and runDprCase take an optional projection.
- text-latin-run.ts runs the engine, chrome-dual plus a per-node face key (via font-reference platformFonts, as fonts-run.ts does), DPR 1, 2, 3 and 2.625, and breaks N/N, with captures under expected-text-latin/**.
- The translate harness gets a transcript replay shaper; TS, Swift and Kotlin replay the text-latin vectors outside the declared lanes.
- The web refusal is lifted, DRAGON_SYNTHETIC_FONT_STYLE is added, and the R6 italic gate cases are added.

**Added files and hunks:**
- environment.ts: face in FontSpec; fontLengths passes face; the ex fault applies to Ahem only.
- project.ts: the deferral Set, engine-mode lowering and engineLowered.
- internal.ts: append.
- text-latin-run.ts, cli/text-latin-capture.ts and expected-text-latin/**: new.
- fonts-run.ts: additive exports only.
- cli/capture.ts, cli/report.ts and gen-profile-rows.ts: one TEXT_LATIN_FIXTURES loop each, mirroring FONT_FIXTURES.
- translate/src corpus.ts and corpus-dpr.ts are exempt from S16, append-only. This resolves the spec contradiction.

**Strictness verify:**
- git diff of targets.ts, device-lanes.ts, native-host.ts, lanes.ts, line-breaks.ts, native-build.ts, break-capture.ts and dpr-capture.ts is empty.
- layoutCases() and nativeCases() ids are pinned equal to BASE.
- engineLayoutProjection deep-equals nativeLayoutProjection on every FIXTURES case at every DPR.
- Native mode still refuses Lato and Inter with the existing message.
- shapedMeasurerFor is byte-identical to measurerFor on every FIXTURES case and vector.
- shapedMeasurer Ahem equals Chrome on T082's 1680/1680 runs.
- DRAGON_SYNTHETIC_FONT_STYLE fires on no existing case.
